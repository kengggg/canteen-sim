# Canteen Sim — Plan 3: Batch Runs and Statistics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn single runs into evidence (spec §10): reservation and sensitivity sweeps over paired seeds, paired-t
statistics with the free-flow-advantage sign, win counts, fixed result wording, CSV export, an executor layer (sync,
time-sliced main thread, worker pool with health check and fallback), and the Node precompute of the default sweep.

**Architecture:** `src/batch/` is plain TypeScript with no DOM imports except behind injected factories. A *job* is
one engine run; a *batch* is a list of jobs plus aggregation. Executors take jobs and return `RunResult`s; the
aggregator pairs each level run with its 0% baseline for the same seed (and sweep value) and computes PairMetrics and
statistics. The worker entry is a thin wrapper over the same `runJob`.

**Tech Stack:** as Plans 1–2. Worker specifics are exercised with fake workers in Vitest; real-browser worker
equivalence is Plan 4's Playwright suite.

**Spec:** `docs/superpowers/specs/2026-09-24-canteen-sim-design.md` §7.2–7.5 (metric catalogue), §10 (all), §13.7.

**Plan form (ruling, as Plan 2):** tasks list files, interfaces and every test; code is written under TDD in the task.

## Global Constraints

- Seeds: `seed_1 = seed`, `seed_i = hash4(seed, 11, i, 0)` for `i = 2…n`; `n ∈ {30, 60, 120}` in the UI, any `n ≥ 2`
  in tests.
- Reservation sweep levels `{0, 0.25, 0.5, 0.75, 1}`; 0 is the baseline (no interval, no win count). Primary endpoints
  read at 1.0 vs 0.
- Sensitivity sweep: 3–6 values of one scalar setting (not seed, `reserve.percentA`, `crowd.groupMix`); for each value
  0 vs the current `percentA` (1.0 if that is 0) on the same seeds; every value validated first (blocked → stop with a
  message naming it); a `seatsPerSide` sweep clamps `shareMinEmpty` per value.
- t-table for df ≤ 29 exactly as spec §10.3; Cornish–Fisher with `z = 1.959964` for df ≥ 30. No interval when
  `n_used < 10`. Flags: all zero → "identical in all n lunches"; all equal ≠ 0 → "the same in every lunch"; > half
  exactly 0 → "mostly ties — interval approximate".
- Free-flow advantage = `A − B` for lower-is-better, `B − A` for higher-is-better. Positive = free flow better.
- A seed is dropped from a statistic if either side is `null` or truncated.
- `src/batch/stats.ts` is under the determinism allowlist (spec §8.5).
- Worker pool: `hardwareConcurrency − 1` workers (min 1); a worker must answer `{type:'ping'}` with `pong` within 3 s
  and fire no `error`; otherwise fallback. Fallback slices ≤ 12 ms, yielding via `MessageChannel`.
- CSV numbers use `Number.prototype.toString`; timestamps ISO 8601 UTC; header comment holds settings JSON,
  `MODEL_VERSION` and build SHA.

## Review Focus

1. **Null and truncated seeds** mixed into a level. Expected: dropped pairwise, `n_used` reported. Test: Task 1.
2. **Blocked sensitivity value** (e.g. `stallCount` making frontage < 1.8 m). Expected: sweep refuses before running,
   naming the value. Test: Task 2.
3. **Worker that never answers ping / throws / errors mid-run.** Expected: fallback executor finishes the batch with
   identical hashes. Test: Task 4.
4. **Cancel mid-batch.** Expected: partial results discarded, no further jobs run. Test: Task 4.
5. **Precompute determinism.** Expected: the embedded hashes equal a fresh run. Test: Task 6.

## File Structure

| File | Responsibility |
|---|---|
| `src/batch/stats.ts` | t critical values, paired statistics with flags, win counts, advantage sign |
| `src/batch/catalog.ts` | Metric catalogue: id, label, unit, better, class (primary/secondary/diagnostic), extractor |
| `src/batch/sweep.ts` | Seeds, job lists for both sweeps, per-value validation |
| `src/batch/runner.ts` | `runJob`, `aggregate` (pairing, PairMetrics, stats per level), `Batch` controller |
| `src/batch/executors.ts` | Sync executor, time-sliced main-thread executor, worker pool with health check and fallback |
| `src/batch/worker.ts` | Worker entry (`ping`/`run`) |
| `src/batch/wording.ts` | §10.4 sentence templates |
| `src/batch/csv.ts` | CSV export |
| `src/batch/precompute.ts`, `scripts/precompute.ts` | Default reservation sweep → `src/generated/evidence.json` |

### Task 1: Statistics

Tests (§13.7): hand-computed paired-t CI with df from the table (n = 10) and from the expansion (n = 40); all-zero,
all-equal and mostly-ties flags; no interval under 10; win/tie/loss with ties; advantage sign for both directions;
null/truncated dropping.

### Task 2: Metric catalogue and sweeps

Tests: seeds formula (`seed_2 = hash4(seed, 11, 2, 0)`); reservation sweep has `5n` jobs; sensitivity sweep has
`values × 2 × n` jobs using `percentA` (or 1.0 when 0); a blocked value is refused with its name; `seatsPerSide`
sweep clamps `shareMinEmpty`; catalogue has P1–P4 marked primary with the right direction.

### Task 3: Runner and aggregation

Tests: `runJob` equals a direct engine run (hash, metrics); aggregation pairs by (seed, value), computes PairMetrics
with the pair's peak window, P3 advantage uses it; baseline level has no stats; truncated seeds dropped.

### Task 4: Executors

Tests: sync executor order-independent results; sliced executor yields between slices (fake scheduler) and matches
sync hashes; worker pool with fake workers: healthy pool matches sync; ping timeout → fallback; worker `error` event
mid-run re-queues on the fallback; cancel discards partial results.

### Task 5: Wording and CSV

Tests: the three §10.4 templates render with fixed number formatting; CSV header comment (settings JSON, model,
SHA), one row per run with every RunMetric column and per-size columns, `pair_` rows with `pair_peakWindowStart`;
numbers via `toString`.

### Task 6: Precompute

Tests: `npm run precompute` writes `src/generated/evidence.json` (150 runs, hashes, RunMetrics, PairMetrics) of
≈ 60 KB; a fresh run of any listed job reproduces its hash.
